# Ask TeamCraft (assistant)

*Ask TeamCraft* is an optional assistant built into the server. Claude
answers questions about your PDM data. It looks things up with the same
tools that the [MCP server](../reference/mcp.md) offers to external AI
clients, and it uses **your rights**. It answers on the server, so nothing
has to be installed on your computer.

It is meant for the reading and summarising work around a release, not for
CAD generation:

| Where                 | Quick action                 | What you get                                                                                     |
|-----------------------|------------------------------|--------------------------------------------------------------------------------------------------|
| Revision page         | **Draft release notes**      | what changed compared with the previous revision: attributes, files, BOM, open points            |
| Revision page         | **Check before release**     | a checklist: blocking items (unreleased BOM children and references, check-outs) and warnings     |
| Change order page     | **Brief me for this review** | what changes, the impact on dependents outside the change, risks, questions for the author       |
| Dashboard             | **What needs my attention**  | an ordered to-do list from your worklist: reviews, impacts, old check-outs, your drafts           |
| Everywhere            | **Ask**                      | any question, e.g. "Which assemblies use PRT-000012, and are they released?"                     |

Open it with **Ask TeamCraft…** on the page (desktop app: **Ask…** in the
toolbar of a revision or change tab). You can add your own words to a quick
action, e.g. "focus on the weld seams". The answer shows the tools that the
assistant used. Item numbers in the answer link to the item. Every
question starts fresh: the assistant does not remember earlier questions.

## What it can and cannot do

- **Read-only by default.** It can read what you can read and nothing else.
- **Drafts only when you allow them.** CAD editors can tick *Allow drafting
  change orders*. The assistant can then create a draft change order or add
  revisions to one of your drafts. It never submits, approves, releases or
  makes anything obsolete. Those decisions stay with people.
- **Check the answer.** It is generated by an AI model from the data that
  the tools return. Numbers, states and quantities come from TeamCraft, but
  check them before you rely on them.
- **Limits.** One question may take up to 12 model steps (configurable) and
  4 minutes. Ask a narrower question when a limit is reached.

## Privacy

The assistant is **off** unless an administrator configures an Anthropic
API key (`TEAMCRAFT_ANTHROPIC_API_KEY`, see
[Configuration](../admin/configuration.md#assistant-optional)). Without a
key no data leaves the server, and the buttons are hidden.

When it is on, your question, the instruction of the quick action and the
results of the tools it calls are sent to the Anthropic API. This includes
item names, descriptions, BOM lines and change order texts. Files are not
uploaded; only their names and metadata are. The API key stays on the
server. Browsers and the desktop app never see it. The audit log records
each run (`assistant.run`): who asked, which quick action, the length of
the question, the tools used and the token counts. The audit log never
stores the question or the answer.

## API

```http
GET  /api/v1/assistant          → {enabled, model, actions: [{id, label, needs}]}
POST /api/v1/assistant
     {"action": "release_check", "context": {"item": "ASM-000003", "revision": "B"}}
     {"question": "Where is PRT-000012 used?", "allow_drafts": false}
```

`action` is one of `ask` (default, needs `question`), `release_notes` and
`release_check` (need `context.item`, optional `context.revision`),
`review_brief` (needs `context.change`) and `attention`. The answer contains
`answer.text` (markdown), `answer.truncated`, `tools` (`[{name, ok}]`),
`steps`, `model` and the token counts. `GET /api/v1/me` reports
`capabilities.assistant`. Without a key the `POST` endpoint answers `404`.
When the AI service is overloaded or busy it answers `503`.

## Follow-up: local agents in the desktop app (ACP)

The [Agent Client Protocol](https://agentclientprotocol.com) (ACP) connects
editors to coding agents that run on the user's machine (Claude Code,
Gemini CLI and others). A planned follow-up is to let the desktop app act as
an ACP client. A local agent would then work on the workspace of a
checked-out revision and reach the PDM data through the MCP server with the
user's own token. The server would need no API key. This is **not
implemented yet**. Today, local agents connect through
[MCP](../reference/mcp.md).
